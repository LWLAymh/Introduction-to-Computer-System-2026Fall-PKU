# 往年题 · 按知识点分类

把 `往年题/` 里的历年期中、期末、阶段测验、Lab 测验试卷，按 CSAPP 的 9 个知识模块重新整理，
每个模块一份清单 + 该模块下所有题目的**逐字原文**。

## 怎么用

1. 先看 **[00-总览.md](00-总览.md)** —— 一张「试卷 × 模块」交叉表，能看出每个模块历年考了多少题、
   哪几年是重点。
2. 再进 **[模块/](模块/)** 下对应的文件复习。每个模块文件分三节：
   - **一、清单** —— 这个模块下有哪几年的哪些题，以及每题考什么；
   - **二、题目原文** —— 按试卷顺序贴出每道题的原文（含选项、代码、表格、图片引用）；
   - **三、相关试卷的参考答案 / 解析原文** —— 该模块涉及的试卷，其卷末答案/解析块的原文。
3. 需要看某份卷子的全貌时，去 **[原文/](原文/)** —— 每份试卷完整的 Markdown 全文。

## 方法是怎样的（以及为什么可信）

这份整理里，**题目正文是逐字原文，没有经过任何转述或改写**。做法上做了一个刻意的设计：

- 分类环节（由若干个子任务并行完成）**只输出「行号区间 → 模块」的映射**，
  例如「`原文/期末/2024期末-带答案.md` 第 45–78 行属于 Data Representation」。
  它不抄写、不复述任何题目文字。
- 然后由脚本 [`_tools/build_modules.py`](_tools/build_modules.py) 按这些行号，回到
  `原文/` 里**按行切出**原文，拼进模块文件。

这样从根上杜绝了「转述时把题目改错」这一类失真：模块文件里的每一个字都来自原始转换结果。
`_cls/` 里存的就是那些行号映射（JSON），可以随时复核。

### 转换链路

```
往年题/*.pdf, *.docx
      │  _tools/convert.py        pdfplumber 抽字 + 逐页渲染插图
      ▼
原文/**/*.md                       每份试卷的 Markdown 全文（保留 <!-- page N --> 标记）
      │  （两份纯扫描件改由人工/视觉逐页誊写，见下）
      │  分类 -> _cls/*.json        只记行号区间，不记文字
      ▼  _tools/build_modules.py    按行号切原文
模块/*.md  +  00-总览.md
```

### 三份特殊处理的卷子

这三份是**纯扫描图像**（或双栏交错）导致自动抽字失败，改为逐页读图人工誊写：

- `期中/2014期中-带答案.pdf` —— 内嵌 SimSun 子集字体既无 ToUnicode 也无 cmap 表，
  且字形轮廓与系统字体匹配率过低（约 28%），无法反查。已渲染全部 18 页后据图重誊。
- `期中/2012期中-带答案.pdf` —— 双栏排版，抽取时两栏被逐字符交错拼接。
  已渲染全部 13 页后据图重誊（该卷为英文卷，保留英文原文）。
- `期末/2022期末-无答案.pdf` —— 纯扫描件，文本层为空。已渲染全部 15 页后据图重誊。

其余试卷都由 `pdftotext`/`pdfplumber` 正常抽取；早期几份 Word 导出的 PDF 存在
「字体基线偏移导致行内乱序」问题，已在 `convert.py` 里用「中文锚点字体 + 行内按 x 排序」修正。

### 同一份卷子出现两次的处理

`期中/2015期中-带答案.md` 与 `期末/2015期末-20151109-带答案.md` 是**同一张卷子**
（正文逐行相同，只有插图路径不同），整理时只在模块清单里保留一份，另一处以
「⚠️ 同一份卷子也存在于……」标注。判定用的是正文指纹（忽略标题行、来源行与图片路径）。

注意区分另一种情况：`2025期末-带答案` 与 `2025期末-无答案` **不是**重复。
前者是答案速查表（题干被截断，只保留「1. 观察下面的 C 程序代码：」这类残句 + 答案），
后者是完整题面。两者互补，都保留。

### 没有题目的材料

`期中/2024期中-试题及答案勘误.md` 是评分勘误说明，本身不含题目，因此不出现在任何
清单里。但它的内容（哪几道小题改判满分）对其涉及的模块有用，所以在 `_cls/` 的 JSON 里
用 `applies_to` 指明它注解的是哪几份卷子，脚本会把它作为「参考答案 / 解析」追加到
2024 期中触及的那 5 个模块末尾。

## 已知不足

- **粒度不是绝对均匀**：分类是按「小题」切的，但个别题目横跨多个知识点时，只能选一个主导模块，
  并在清单的「考什么」一列里说明。若某题你认为是别的模块，直接看 `_cls/` 里的行号去改即可。
- **答案与题目的对应**：很多卷子把答案集中放在卷末，无法可靠地一一对应到小题。
  模块文件里把这些答案块作为「三、相关试卷的参考答案 / 解析原文」整块附上，而不是硬塞到每题下面。
- **2012期中为英文卷**，其题号体系（`Problem A`）与其他卷不同。
- 原始 PDF 里少量印刷错误按原样保留，未作修正。
- **少数卷子的反汇编 / 十六进制区段存在行内交错**（见下）。

### 行内交错：怎么回事、影响了多少

一些由 Word 导出的 PDF，会在**同一条基线上叠放多个文本片段**（典型是「代码 + 行末的
`(1)` `(2)` 填空编号」，或反汇编清单 + 十六进制 dump）。抽取时这些片段被交错拼接，于是
出现 `ac[oiu+n1t] +=+ ;f (a[i], (5) );` 这样的乱码级行。

这不是可以靠排序规则修好的——两个片段在 PDF 里本来就是重叠的，只有看图才能还原，
所以按原样保留。用 `_tools/find_interleave.py` 可以量化：以「ASCII 字母数字里相邻重复
字符占比 ≥ 0.28 且含至少 6 个字母」为判据扫全文，结果写在 `_tools/_interleave.txt`。

影响范围是**局部且有限**的：全部 42 份材料里，最严重的一份（2014期中）727 行中有 32 行
受影响（4.4%），多数在 1% 以下；且集中在反汇编、十六进制 dump、填空代码这几类区段，
**文字叙述段落和绝大多数正常代码不受影响**。受影响的卷子主要是：

| 材料 | 受影响行 | 位置 |
|---|---|---|
| 期中/2014期中-带答案.md | 32 / 727 | 主要是反汇编与填空代码 |
| 期末/2018期末-带答案.md | 27 / 920 | 反汇编清单 |
| 期中/2021期中（带/无答案） | 27 / 723、20 / 527 | 十六进制 dump |
| 期中/2020期中（带/无答案） | 25 / 471、14 / 333 | 反汇编 |
| Lab测验/2025Lab测验-无答案.md | 23 / 875 | 十六进制 dump |

需要完全干净的版本时，可以照着 `assets/` 里对应页的渲染图核对——或按同样的
「渲染 + 读图誊写」流程重做那几页。

## 校验

两个脚本，都是可重复跑的：

- `_tools/validate_cls.py` 检查每份分类 JSON：区间是否升序不重叠、是否越界、
  模块名是否在白名单内。当前 **42 份全部通过**（`checked 42 bad 0`），
  报告见 `_tools/_cls_report.txt`。
- `_tools/verify_verbatim.py` 回查「逐字原文」这个说法本身：把 `_cls/` 里每个行号区间
  重新从 `原文/` 切一遍，确认这段文字原样出现在对应模块文件里。当前结果是
  **命中 1027，未命中 0**；另有 6 条预期未命中，全部来自被去重的 2015 别名卷
  （正文已由 `期中/2015期中-带答案.md` 承载）。报告见 `_tools/_verify.txt`。

换句话说：模块文件里 1009 道题的文字，全部经过「重新切一遍再比对」的检验，没有一处
是转述或改写的。

## 复现

```bash
python _tools/convert.py          # PDF/DOCX -> 原文/*.md + assets/
python _tools/render_all.py 期中/2012期中-带答案.pdf   # 需要时整卷渲染
python _tools/find_interleave.py  # 扫行内交错，结果写 _tools/_interleave.txt
python _tools/validate_cls.py     # 校验 _cls/ 里的行号区间
python _tools/build_modules.py    # 生成 模块/*.md 与 00-总览.md
python _tools/verify_verbatim.py  # 回查模块里的题是否逐字等于原文
```

改分类只需动 `_cls/*.json` 里的行号，再跑后两条命令即可，题目正文一个字都不用碰。
